Distributed Translation Lookaside Buffers (TLB)

Module Card

  • RTL file: N/A
  • Status: Draft

1. Overview

The Translation Lookaside Buffers (TLB) are distributed, high-speed Content-Addressable Memory (CAM) arrays embedded directly within the L1 Instruction Cache (Stage 1) and L1 Data Cache (Stage 6) subsystems. They cache recent virtual-to-physical address translations (VA -> PA) along with pre-evaluated Physical Memory Protection (PMP) and Physical Memory Attribute (PMA) metadata to enable single-cycle memory access.

2. Distributed TLB Partitioning

Subsystem Parameter Name Default Entries Matching Mode Target Pipeline Stage
I-TLB ITLB_ENTRIES 16 Fully-Associative CAM (Tree-PLRU) Stage 1 (Instruction Fetch)
D-TLB DTLB_ENTRIES 32 Fully-Associative CAM (Tree-PLRU) Stage 6 (Memory Execution)

TLB Entry Layout (Variable-Mask CAM Entry)

To support arbitrary Physical Memory Protection (PMP) bounds (down to NA4 4-byte granularity and arbitrary NAPOT power-of-two regions) alongside standard Sv39 page sizes (4 KiB, 2 MiB, 1 GiB), each TLB entry covers a range equal to \(\min(\text{Page Size}, \text{PMP/PMA Region})\). The entry layout is defined as:

Field Width Description
valid 1 Entry contains a valid translation and permission cache
is_bare 1 Entry was allocated in BARE mode (1:1 identity mapping, bypasses page table lookup but caches PMP/PMA checks)
asid 16 Address Space Identifier (for Sv39 mode; ignored in BARE mode)
va_tag 37 Virtual Address tag bits (VA[38:2]) used for CAM comparison
pa_tag 54 Physical Address translation payload (PA[55:2])
mask 37 Comparison mask (1 = match bit, 0 = ignore bit) covering \(\min(\text{Page Size}, \text{PMP/PMA Region})\)
pte_flags 8 RISC-V PTE permission & attribute flags (R, W, X, U, G, A, D)
pmp_fault 1 Pre-evaluated PMP access fault flag for the range covered by this entry
pma_cacheable 1 Pre-evaluated PMA cacheability attribute (1 = Cacheable DRAM, 0 = Non-cacheable MMIO)
pma_amo_level 2 Pre-evaluated PMA atomic capability level (None, Swap, Logical, Arithmetic)

PBMT Integration into TLB Attributes

Page-Based Memory Type bits (PTE[62:61] - PBMT) from the Sv39 page table are consumed by the PMA Checker during the PTW REFILL phase. The combined attributes (post-PBMT override) are cached directly in the TLB entry as pma_cacheable and pma_amo_level. Consequently, separate dedicated PBMT bit storage is not required in the TLB CAM, saving area and registers.

3. VIPT Timing Integration and CAM Lookup Logic

To meet the 100 MHz clock timing (\(T_{clk} = 10\text{ ns}\)) on the 130nm ASIC process, the TLBs operate in parallel with L1 Cache SRAM tag indexing using Virtually Indexed, Physically Tagged (VIPT) timing:

                  Virtual Address (VA[38:0])
                             │
           ┌─────────────────┴─────────────────┐
           ▼                                   ▼
     [ VA[11:0] Index ]                 [ VA[38:2] Lookup Tag ]
           │                                   │
           v                                   v
    +--------------+                    +--------------+
    | L1 Cache     |                    | TLB CAM      |
    | SRAM Array   |                    | Array Lookup |
    +------+-------+                    +------+-------+
           │ SRAM Tag                          │ Physical PA[55:2] + Flags
           └─────────────────┬─────────────────┘
                             v
                  [ Physical Tag Comparator ] ──► Single-Cycle Hit / Miss

CAM Lookup Matching Rules:

An entry \(i\) is considered a Hit if all of the following conditions are met:

  1. entry.valid == 1
  2. Address Match under Mask: (VA[38:2] & entry.mask) == (entry.va_tag & entry.mask)
  3. Privilege & Translation Mode Match:
    • In BARE Mode (identity mapping): Matches only if entry.is_bare == 1.
    • In Sv39 translation Mode: Matches only if entry.is_bare == 0 AND either:
      • Global Page: entry.pte_flags.G == 1
      • ASID Match: entry.asid == satp.ASID

Physical Address Generation on Hit:

When an entry hits, the resulting 56-bit Physical Address is generated by combining the translated base from pa_tag with unmasked low-order address bits:

\[ \text{PA}[55:2] = (\text{VA}[55:2] \ \& \ \sim\text{entry.mask}) \ | \ (\text{entry.pa_tag} \ \& \ \text{entry.mask}) \]
\[ \text{PA}[1:0] = \text{VA}[1:0] \]

The TLB simultaneously outputs pmp_fault, pma_cacheable, pma_amo_level, and pte_flags.

4. Replacement Policy: Binary Tree-PLRU

To guarantee deterministic, high-efficiency victim selection without the hardware overhead of true LRU, both TLBs employ a Binary Tree Pseudo-LRU (Tree-PLRU) algorithm.

4.1 Tree State Representation

  • I-TLB (16 entries): 4-level binary tree requiring \(16 - 1 = \mathbf{15\text{ bits}}\) of state (plru_tree[14:0]).
  • D-TLB (32 entries): 5-level binary tree requiring \(32 - 1 = \mathbf{31\text{ bits}}\) of state (plru_tree[30:0]).

4.2 Victim Selection (on TLB Refill)

  1. Invalid Entry Priority: If any entry has valid == 0, the lowest-index invalid entry is selected immediately without consulting the PLRU tree.
  2. PLRU Tree Traversal: If all entries are valid (valid == 1), the FSM traverses the tree from root (Node 0):
    • At each node, if the bit is 0, branch to the left child; if 1, branch to the right child.
    • The reached leaf index designates the replacement victim (PLRU Victim).

4.3 State Update (on TLB Hit or Refill)

Upon a hit or refill at entry index \(K\):

  • All tree node bits on the path from root (Node 0) to leaf \(K\) are inverted to point away from \(K\), protecting the newly referenced entry from eviction in subsequent cycles.

5. TLB Invalidation and Lifecycle Rules

5.1 SFENCE.VMA Invalidation

When an SFENCE.VMA instruction commits in Stage 7, an invalidation pulse (sfence_vma_valid_i) is broadcast to both TLBs:

always_ff @(posedge clk_i or negedge rst_ni) begin
  if (!rst_ni) begin
    for (int i = 0; i < TLB_ENTRIES; i++) tlb_array[i].valid <= 1'b0;
  end else if (sfence_vma_valid_i) begin
    for (int i = 0; i < TLB_ENTRIES; i++) begin
      // Global pages (G=1) and BARE mode entries are preserved across SFENCE.VMA
      if (!tlb_array[i].pte_flags.G && !tlb_array[i].is_bare) begin
        if ((sfence_vma_asid_i == 16'd0 || sfence_vma_asid_i == tlb_array[i].asid) &&
            (sfence_vma_addr_i == 64'd0 ||
             ((sfence_vma_addr_i[38:2] & tlb_array[i].mask) == (tlb_array[i].va_tag & tlb_array[i].mask)))) begin
          tlb_array[i].valid <= 1'b0;
        end
      end
    end
  end
end

5.2 PMP CSR Modification Invalidation

While is_bare == 1 entries are exempt from SFENCE.VMA, they cache pre-evaluated PMP permission flags. When any PMP CSR (pmpcfg* or pmpaddr*) is written:

  • The resulting pipeline flush clears all TLB entries with is_bare == 1 to prevent stale security permissions from being used.

Preservation Rules

  • SFENCE.VMA invalidates Sv39 non-global mappings matching address/ASID filters.
  • PMP CSR Writes invalidate all BARE mode mappings across both TLBs.
  • satp writes trigger a full pipeline flush and flush all non-global Sv39 entries.
  • Entries with Global flag G == 1 or is_bare == 1 are exempt from standard SFENCE.VMA flushes and remain valid across context switches.

6. Verification

The TLB arrays and Tree-PLRU replacement logic are verified through formal assertion checking (SVA) and functional simulations:

Formal SVA Assertion Table

Assertion ID Property / Condition Severity Checkpoint Description
SVA_TLB_01 $onehot0(hit_vector) FATAL CHK-MMU-03 CAM lookup must never yield multiple conflicting entry hits for a single VA
SVA_TLB_02 (sfence_vma_valid_i && (is_bare || pte_flags.G)) |=> (entry_valid) ERROR CHK-MMU-05 SFENCE.VMA must strictly preserve BARE mode and Global (\(G=1\)) mappings
SVA_TLB_03 pmp_write_valid_i |=> (!entry_valid || !is_bare) FATAL CHK-MMU-05 Any PMP CSR write MUST invalidate all cached BARE TLB entries
SVA_TLB_04 (sfence_vma_valid_i && (sfence_asid != 0) && (entry.asid != sfence_asid)) |=> (entry_valid) ERROR CHK-MMU-05 SFENCE.VMA with non-zero ASID must not invalidate entries with distinct ASIDs
SVA_TLB_05 (refill_valid && has_invalid_entry) |-> (victim_idx == first_invalid_idx) ERROR CHK-MMU-06 TLB replacement must always prioritize invalid entries over PLRU eviction

Coverage Strategy

  • CAM Hit Matrix: 100% coverage of single hits across all 16/32 entry indices.
  • SFENCE Permutations: Testing full invalidate (rs1=0, rs2=0), address-only (rs1!=0, rs2=0), ASID-only (rs1=0, rs2!=0), and address+ASID (rs1!=0, rs2!=0).
  • PLRU Eviction Distribution: Uniform distribution verification across replacement cycles without hot-spot starvation.
